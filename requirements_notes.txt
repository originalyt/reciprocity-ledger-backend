需求记录（礼账程序）

背景
- 当前处于需求讨论阶段，需要把已确认需求持续记录在一个 txt 文件中。

已确认的最小可用功能（数据产生起点）
1) 添加一笔随礼
   - 字段：对应人、关系、事件、金额

2) 添加一笔收礼
   - 字段：对应人、关系、时间、金额

说明
- 以上两类“新增记录”是礼账数据产生的最基础入口。

3) 联系人维护（建议纳入最小版本）
   - 新增随礼/收礼时，可选择已有联系人，或直接新建联系人
   - 联系人最小字段：姓名（必填）、关系（可填）
   - 可选字段：手机号、备注
   - 目的：避免“对应人”重复录入，保证后续统计准确性

4) 统计维度
   - 支持按“个人”统计：个人随礼统计、个人收礼统计
   - 支持按“时间段”统计对应总数（默认按总金额统计，可同时展示笔数）
   - 支持与“某个人”的往来统计：
     * 对该个人的随礼总金额/笔数
     * 来自该个人的收礼总金额/笔数
     * 可按时间段筛选后统计

5) 数据时间字段补充（关键）
   - 随礼与收礼记录都必须包含“礼金发生时间”（业务时间）
   - “礼金发生时间”不等于“数据创建时间”
   - 创建时间仅用于系统审计，不作为业务统计的唯一依据

需求讨论已确认（v1 基线）

1) 记录类型
- 随礼、收礼

2) 记录主体规则
- 单条记录仅涉及双方：你 + 1 个联系人
- 新增记录必须关联联系人：可选已有；没有可现场新增

3) 联系人字段
- 姓名（必填）
- 关系（可填）
- 手机号（可填）
- 备注（可填）

4) 事件字段
- 事件类型（下拉）+ 事件说明（可选）
- 事件类型包含：婚礼/订婚、满月/百日/周岁、生日、升学/毕业、乔迁、丧事（白事）、探病慰问、节日往来、生育探望、其他

5) 去重规则
- 同一记录唯一键：联系人 + 事件类型 + 事件说明 + 记录类型（随礼/收礼）
- 若重复新增，拦截并提示：该记录已存在，请编辑原记录

6) 金额与备注
- 金额记录最终值
- 可通过备注说明过程
- 金额统一显示两位小数

7) 修改与删除
- 支持修改记录（包括金额、事件、时间、备注等）
- 不提供删除功能（无物理删除、无逻辑删除）

8) 时间与统计口径
- 统计一律按“礼金发生日期”
- 时间粒度：YYYY-MM-DD
- 创建/修改时间仅用于审计，不参与业务统计

9) 首页统计默认指标
- 总随礼金额
- 总收礼金额
- 往来净额（收-随）

10) 默认统计时间范围
- 今年（例如 2026-01-01 至 2026-12-31）

11) 统计增强（新增确认）
- Top 往来联系人（收礼 Top、随礼 Top）
- 默认排序：按总金额降序
- 默认展示字段：联系人姓名、总金额、笔数、最近往来日期
- 默认数量：Top 10
- 默认时间范围：今年（支持切换时间范围）

12) 时间线能力分层（新增确认）
- 基础时间线（一级）：随礼、收礼、混合（默认）
- 其他均作为展示角度/筛选维度，不新增为独立时间线类型

时间线展示角度（筛选/分组）
- 按联系人（即“与某人的时间线”）
- 按事件类型
- 按关系
- 按时间段（默认今年）
- （可后续扩展）按金额区间

统计规则
- 所有统计基于“当前筛选结果”计算
- 混合时间线额外展示净额：收礼总额 - 随礼总额


13) 同事件回礼识别（变更确认）
- 目标：识别“同联系人 + 同事件”是否形成收礼/随礼成对记录
- 配对键：联系人 + 事件类型 + 事件说明（事件说明为空按空串参与配对）
- 配对状态：
  * 已互回：同时存在随礼记录和收礼记录
  * 待对方回礼：仅存在随礼记录
  * 我待回礼：仅存在收礼记录
- 金额展示：展示随礼金额、收礼金额、事件净额（收礼金额 - 随礼金额）
- 展示字段：联系人、事件类型、事件说明、状态、随礼金额、收礼金额、事件净额、最近发生日期
- 识别粒度：按“联系人 + 事件”识别（事件级配对）
- 数据口径：基于全部历史数据（不只今年）
- 交互：支持点击进入该“联系人 + 事件”的双向记录明细
- 说明：当前唯一键规则下，同一配对键每种记录类型最多 1 条记录（由去重规则保证）
14) 前端技术选型（新增确认）
- 目标端：手机 App（Mobile First）
- 覆盖平台：Android 与 iOS（同一套代码）
- 开发语言：Dart
- 前端框架：Flutter 3.x
- UI 方案：Material 3（移动端组件体系）
- 状态管理：Riverpod
- 网络请求：Dio（统一拦截器与错误处理）
- 页面路由：go_router
- 图表组件：fl_chart（用于趋势与 Top 统计）
- 本地存储：shared_preferences（筛选条件与草稿）

15) 后端技术选型（新增确认）
- 后端框架：Spring Boot
- 数据库：PostgreSQL
- ORM：MyBatis-Plus
- 鉴权：多用户 + 无密码登录（手机号短信验证码为主，支持第三方登录扩展）+ JWT（Access Token）与 Refresh Token

需求模块划分与功能拆解（v1）

一、需求模块划分（业务视角）
1) 账号与鉴权模块
2) 联系人管理模块
3) 礼账记录模块（随礼/收礼）
4) 记录去重与数据校验模块
5) 时间线与筛选模块
6) 统计分析模块
7) 同事件回礼识别模块
8) 首页总览模块
9) 系统审计与基础配置模块

二、各模块功能拆解与描述

1) 账号与鉴权模块
- 无密码登录
  * 功能描述：用户通过手机号+短信验证码登录，登录成功后签发 Access Token 与 Refresh Token。
  * 规则：验证码有有效期、错误次数限制、频次限制。
  * 结果：返回用户身份信息、token、token 过期时间。
  * 异常：验证码错误、验证码过期、手机号未注册或被禁用。

- Token 刷新
  * 功能描述：Access Token 过期后，客户端使用 Refresh Token 获取新 Access Token。
  * 规则：Refresh Token 过期或失效时需重新登录。
  * 异常：token 被撤销、token 不匹配。

- 多用户隔离
  * 功能描述：所有联系人、记录、统计数据都按用户隔离。
  * 规则：任何查询和修改必须带当前用户上下文。

2) 联系人管理模块
- 新增联系人
  * 功能描述：在联系人页新增，或在新增礼账记录时“现场新增”。
  * 字段：姓名（必填）、关系（可填）、手机号（可填）、备注（可填）。
  * 校验：姓名非空；手机号格式合法（若填写）；同一用户下可做“姓名+手机号”弱去重提醒。

- 编辑联系人
  * 功能描述：修改关系、手机号、备注、姓名。
  * 规则：编辑后不影响历史记录归属，仅更新联系人主数据展示。

- 联系人查询与选择
  * 功能描述：新增记录时可搜索并选择已有联系人。
  * 排序建议：最近往来时间倒序，其次姓名拼音/字母排序。

3) 礼账记录模块（核心交易模块）
- 新增随礼记录
  * 功能描述：录入一笔“我给某联系人”的礼金记录。
  * 字段：联系人、记录类型=随礼、事件类型、事件说明（可选）、礼金发生日期、金额、备注（可选）。
  * 业务约束：单条记录仅“你+1联系人”；必须关联联系人。

- 新增收礼记录
  * 功能描述：录入一笔“某联系人给我”的礼金记录。
  * 字段同上，仅记录类型=收礼。

- 编辑记录
  * 功能描述：可修改金额、事件类型、事件说明、发生日期、备注、关联联系人。
  * 约束：编辑后需重新触发去重校验。

- 禁止删除
  * 功能描述：v1 不提供物理删除和逻辑删除入口。
  * 说明：若录错，通过“编辑修正”，并保留审计轨迹。

4) 记录去重与数据校验模块
- 唯一性校验
  * 规则：唯一键 = 联系人 + 事件类型 + 事件说明 + 记录类型。
  * 处理：新增/编辑时命中重复则拦截，提示“该记录已存在，请编辑原记录”。

- 金额校验
  * 规则：金额必须大于 0；最多两位小数；展示统一两位小数。

- 日期校验
  * 规则：必须有“礼金发生日期”；格式 YYYY-MM-DD；统计只认该日期。

- 字段完整性校验
  * 规则：联系人必选、事件类型必选、记录类型必选、发生日期必填、金额必填。

5) 时间线与筛选模块
- 基础时间线视图
  * 类型：混合（默认）、随礼、收礼。
  * 展示：按发生日期倒序；每条显示联系人、类型、事件、金额、发生日期、备注摘要。

- 筛选维度
  * 维度：按联系人、按事件类型、按关系、按时间段（默认今年）。
  * 规则：所有统计都基于“当前筛选结果”实时计算。

- 分组与聚合展示
  * 功能描述：可按联系人或事件类型聚合查看小计。
  * 规则：混合时间线需额外展示净额（收礼总额 - 随礼总额）。

- 详情联动
  * 功能描述：从统计、Top 榜、同事件回礼清单点击联系人后，进入“该联系人混合时间线”。

6) 统计分析模块
- 首页核心指标
  * 指标：总随礼金额、总收礼金额、往来净额（收-随）。
  * 默认时间范围：当前自然年（例如 2026-01-01 至 2026-12-31）。

- 按人统计
  * 指标：某联系人随礼总金额/笔数、收礼总金额/笔数、净额、最近往来日期。
  * 支持：时间段筛选。

- 按时间段统计
  * 功能描述：按选择时间范围统计总金额与笔数。
  * 粒度：先支持日维度汇总，后续可扩月维度。

- Top 往来联系人
  * 榜单：收礼 Top、随礼 Top。
  * 排序：按总金额降序。
  * 默认字段：联系人姓名、总金额、笔数、最近往来日期。
  * 默认数量：Top 10。


7) 同事件回礼识别模块
- 模块目标
  * 对“同联系人 + 同事件”进行双向记录配对，并给出回礼状态标记。
  * 用于回答“这件事是否已互回”，而不是只看联系人总账差额。

- 配对键与识别粒度
  * 配对键：联系人 + 事件类型 + 事件说明（空说明按空串处理）。
  * 识别粒度：事件级配对（不是联系人汇总级）。
  * 基于现有去重规则，同一配对键下每种记录类型最多 1 条。

- 状态判定规则
  * 已互回：同一配对键下同时存在“随礼”和“收礼”两条记录。
  * 待对方回礼：仅存在“随礼”记录。
  * 我待回礼：仅存在“收礼”记录。

- 展示字段
  * 联系人、事件类型、事件说明、状态、随礼金额、收礼金额、事件净额、最近发生日期。
  * 事件净额 = 收礼金额 - 随礼金额（用于金额参考，不影响状态判定）。

- 数据口径与范围
  * 默认按全部历史数据识别，避免被“今年筛选”误判。
  * 支持按时间范围筛选查看，但筛选后结果需明确标注“当前筛选口径”。

- 清单与交互
  * 清单分组：我待回礼 / 待对方回礼 / 已互回。
  * 点击任一条可进入“联系人 + 事件”的双向记录明细。
8) 首页总览模块
- 指标卡片区
  * 展示：总随礼、总收礼、净额。

- 快捷入口区
  * 入口：新增随礼、新增收礼、联系人管理、同事件回礼清单、时间线。

- 榜单区
  * 展示：收礼 Top10、随礼 Top10。

9) 系统审计与基础配置模块
- 审计字段
  * 字段：创建时间、修改时间、创建人、修改人。
  * 规则：仅用于审计，不参与业务统计。

- 事件类型字典
  * 内容：婚礼/订婚、满月/百日/周岁、生日、升学/毕业、乔迁、丧事、探病慰问、节日往来、生育探望、其他。
  * 规则：前后端统一字典编码，避免统计口径不一致。

- 本地偏好存储（App 端）
  * 内容：筛选条件、草稿。
  * 实现：shared_preferences。

三、建议的开发任务包（可直接建迭代）
1) M1 认证与用户隔离
2) M2 联系人 CRUD + 记录页联系人选择
3) M3 礼账记录新增/编辑 + 去重校验
4) M4 时间线与筛选联动
5) M5 统计中心 + Top10
6) M6 同事件回礼识别与清单联动
7) M7 首页总览与导航整合
8) M8 审计字段、字典统一、异常提示完善



四、业务补充需求（建议纳入 v1.5 / v2）

以下内容基于现有需求讨论补充，侧重提升“长期可用性、录入效率、联系人治理、回礼跟进、数据迁移与纠错”能力。

1) 录入效率增强
- 快捷录入
  * 新增记录时支持展示“最近联系人”“常用事件类型”“最近使用金额”快捷项。
  * 默认发生日期为当天，减少重复选择成本。
  * 金额输入可提供快捷档位或最近金额建议。

- 统一新增入口（可选增强）
  * 首页可提供“新增往来”统一入口，进入后再选择“随礼 / 收礼”。
  * 目的：降低首页入口复杂度，统一用户心智。

- 草稿与中断恢复细化
  * 新增/编辑记录页支持自动保存草稿。
  * App 异常退出或主动返回后，再次进入可恢复未提交内容。
  * 草稿至少包含：联系人、记录类型、事件类型、事件说明、日期、金额、备注。

2) 联系人治理增强
- 联系人详情页
  * 展示该联系人的总随礼金额、总收礼金额、净额、最近往来日期。
  * 支持从联系人详情直接进入“该联系人混合时间线”。

- 重复联系人治理
  * 新增联系人时，除“姓名+手机号”弱提醒外，可增加“近似姓名”提醒。
  * 对已存在的重复联系人，后续支持人工合并。

- 联系人合并
  * 功能描述：允许将两个联系人合并为一个主联系人。
  * 规则：历史记录全部迁移到主联系人，保留合并审计记录。
  * 目的：解决重复建档、重名误建问题。

- 联系人归档/停用
  * 功能描述：不常用联系人可归档，默认不出现在常用选择列表中。
  * 规则：归档不影响历史记录与统计结果；必要时可恢复。

- 关系口径标准化
  * 关系字段建议提供预设选项（如亲属、同学、同事、朋友、邻里、业务往来、其他），同时保留自定义补充能力。
  * 目的：提升“按关系统计/筛选”的一致性。

3) 记录纠错与状态管理增强
- 误录纠错机制
  * 在“不提供删除”原则下，建议增加“作废/隐藏”能力，避免完全错误记录长期干扰使用。
  * 作废记录默认不参与业务统计，但保留审计轨迹。
  * 若 v1 不实现作废能力，需在产品说明中明确“仅支持编辑修正”。

- 编辑历史可追溯
  * 记录被修改后，应支持查看最近一次修改信息。
  * 后续可增强为查看完整修改历史（修改前、修改后、修改人、修改时间）。

- 重复提交防护
  * 针对移动端弱网、连续点击等场景，新增记录时应避免重复提交。
  * 目标：防止用户误操作造成重复创建或重复提示。

4) 时间线与搜索增强
- 时间线快捷范围
  * 除默认“今年”外，建议支持“本月”“近 3 个月”“全部”快捷切换。

- 时间线分层
  * 支持三级查看路径：全局时间线 -> 联系人时间线 -> 联系人+事件明细。
  * 目的：从总览快速下钻到某人、某件事。

- 搜索能力
  * 支持按联系人姓名、事件说明、备注进行搜索。
  * 搜索结果仍可继续叠加筛选条件。

- 分组展示增强
  * 时间线可按“月”分组展示，便于长时间跨度查看。
  * 后续可扩展“按事件类型分组”的浏览方式。

5) 统计分析增强
- 净流出 / 净流入视角
  * 在现有“总随礼、总收礼、净额”基础上，增加按联系人查看净流出、净流入排行。
  * 目的：让用户更快识别往来压力与重点对象。

- 按事件类型统计
  * 支持查看各事件类型的随礼金额、收礼金额、笔数、净额。
  * 目的：帮助分析“婚礼类、白事类、节日往来类”等业务分布。

- 趋势统计
  * 支持按日/月查看一段时间内的随礼、收礼、净额变化趋势。
  * 图表仅作为辅助，口径以统计数值为准。

- 统计口径显式展示
  * 所有统计页需明确展示当前时间范围与筛选条件。
  * 避免“全部历史”与“当前筛选结果”混用导致用户误解。

6) 同事件回礼识别增强
- 待办导向能力
  * 对“我待回礼”状态增加更明显入口，支持在首页或模块首页展示待办数量。
  * 目的：把“识别结果”转化为“可跟进事项”。

- 排序与筛选增强
  * 回礼清单支持按最近发生日期、事件净额、联系人名称排序。
  * 支持按状态、时间范围、关系进行筛选。

- 无需回礼 / 回礼豁免
  * 支持对单个“联系人 + 事件”设置“无需回礼”标记，用于表示该事件不再作为待办跟进。
  * 设置粒度为事件级，不按联系人整体设置，避免误伤其他正常往来事件。
  * 适用场景包括：礼节性往来、特殊关系、用户明确判断无需继续回礼等。
  * 建议支持填写豁免原因，如“关系特殊”“礼节性往来”“无需跟进”“其他”。

- 豁免后的状态展示规则
  * 当系统原始识别结果为“我待回礼”或“待对方回礼”时，若被设置为回礼豁免，则业务展示状态改为“无需回礼”。
  * “无需回礼”默认不计入首页待办数量，也不计入待办清单默认统计口径。
  * 回礼清单支持单独查看“无需回礼”分组，或通过筛选查看全部/待办/无需回礼。

- 业务边界说明
  * “无需回礼”是个人业务标记，不改变原始收礼/随礼事实，仅改变待办解释方式。
  * 当前模型基于“同联系人 + 同事件 + 每种记录类型最多 1 条”的前提。
  * 若后续存在“同一事件多次随礼/补礼/补收”场景，需要升级业务规则与数据模型。
  * 在 v1 中应明确向产品与开发说明该边界，避免误判为缺陷。

7) 首页总览增强
- 待办提醒区
  * 展示“我待回礼”数量、最近待处理联系人或事件。

- 最近记录区
  * 展示最近新增或最近修改的礼账记录，便于用户快速回看。

- 快捷操作增强
  * 首页可增加“最近联系人快速录入”能力，减少高频用户的录入步骤。

8) 账号与数据安全增强
- 账号基础功能补充
  * 除登录与刷新 token 外，建议补充退出登录、手机号更换、账号注销等基础能力。

- 多设备与会话管理（后续增强）
  * 支持查看当前登录设备或最近登录记录。
  * 发现异常时可主动失效历史登录状态。

9) 数据迁移与备份增强
- 导入能力
  * 支持从 Excel / CSV 导入联系人与历史礼账记录。
  * 导入前需进行字段校验、去重预检、结果预览。

- 导出能力
  * 支持按当前筛选条件导出礼账记录、联系人统计、回礼清单。

- 备份与恢复
  * 明确是否支持云端同步、换机恢复、手动备份。
  * 该能力即使不在 v1 实现，也建议在需求层提前占位。
